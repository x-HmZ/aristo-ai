# Adaptive Visual-Aid Teaching — Plan

> **Status:** Ready to implement. Avatar overhaul prerequisite is fully verified (2026-05-12, build-v2 branch). ElevenLabs TTS + wawa-lipsync visemes working, gesture state machine live, animations_Avaturn.glb rebuilt via Blender constraint retarget, frustumCulled fix in. Start on branch `adaptive-visuals`.
> **Why now:** Avatars now look right and gesture in sync with narration, but the lesson agent still emits monolithic phase text and a single topic-wide image. The avatar's pointing gesture has nothing to *point at* most of the time, and the image (when it exists) is always a generic "anatomical diagram of the heart" instead of the specific visual that would help land the sentence currently being spoken.

---

## 1. Context — what we want, and what's missing today

### What the user described

> "a multi-stepped teaching division between the normal and then visual with the image generated precisely to support that kind of teaching, where visual parts of the picture are not just generated by the topic, but the part of it that would be helpful to be taught through visual aid, and the image generated in that way — not a fixed structure, but adapting to the topic and the answer being generated by the model."

In plain terms:

- **Per-moment, not per-topic.** When the avatar is mid-sentence saying *"the mitral valve sits between the left atrium and left ventricle"*, the screen should show a cross-section zoomed on the mitral valve specifically — not a generic anatomical poster of the whole heart that's been there since the lesson started.
- **The LLM decides.** Not every sentence needs a picture. The teaching agent reasons about which moments would actually benefit from visual aid and which moments are pure verbal explanation. That decision is content-specific, not schema-specific.
- **Adaptive.** A lesson on Pythagoras has different visual moments than a lesson on photosynthesis has different moments than a lesson on mitosis. The LLM produces the schedule.

### What the codebase looks like today

Confirmed via earlier exploration of [src/lib/agents/teaching.ts](src/lib/agents/teaching.ts), [src/components/learn/LessonView.tsx](src/components/learn/LessonView.tsx), and [src/app/api/generate-model/route.ts](src/app/api/generate-model/route.ts):

| Aspect | Today | What we want |
|--------|-------|--------------|
| Lesson decomposition | 5 phases, each a monolithic text block | Sequence of small narration segments, each ~1–3 sentences |
| Visual decision | Topic-level boolean `should_generate_model` | Per-segment `visual?: {...}` set independently for each segment |
| Image prompt | One `model_image_prompt` for whole lesson | Each visual-bearing segment has its own prompt, narrowly scoped to that moment |
| When image appears | Loaded eagerly during Demonstrate phase only | Swaps in when its segment narrates; swaps out / changes when next segment needs a different visual |
| Phases that get visuals | Demonstrate only | Any phase — Activate, Explain, Challenge setup, Connect — wherever the LLM judges visual aid helps |
| Avatar pointing | Already wired (post-overhaul), driven by `narration_pre_visual` / `visual_walkthrough` boundaries | Driven per segment — points exactly when current segment has a visual |
| TTS sequencing | One `speak()` per phase | One `speak()` per segment, queued sequentially |

The avatar overhaul (`useTTS`, `setGesture`, segment-aware visemes) **already gives us the substrate** — `onEnd` callbacks at narration boundaries, gesture state machine that responds to per-segment hints. What's missing is on the **content side**: the LLM needs to emit segments instead of monolithic phase text, and the image-gen pipeline needs to produce one image per visual-bearing segment.

---

## 2. Approach overview (one paragraph)

Replace the lesson payload's monolithic phase text with an ordered list of `NarrationSegment`s. Each segment carries the text the avatar speaks, the phase it belongs to (so the existing 5-phase UX — phase cards, "next phase" button, progress dots — keeps working), an optional `visual` field that the LLM populates only when *this specific moment* benefits from a picture, and an optional `gesture` hint. After lesson generation, fire all segment image prompts in parallel through a new `/api/learn/segment-visuals` endpoint built on the existing Nano Banana Pro pipeline. A new `useLessonPlayback` hook drives sequential narration: for each segment it sets the active image, sets the gesture, and calls `useTTS().speak()` with the segment text — advancing on `onEnd`. Phase cards render their text by joining their segments. Ship behind `NEXT_PUBLIC_ADAPTIVE_VISUALS=true` with a graceful fallback to the existing phase-block path so we can A/B and roll back instantly.

## 3. Schema changes

### 3.1 New types in [src/lib/agents/teaching.ts](src/lib/agents/teaching.ts)

```ts
export type LessonPhase = "activate" | "explain" | "demonstrate" | "challenge" | "connect";

export type SegmentRole =
  | "narrate"          // generic explanatory speech
  | "hook"             // attention-grabbing opener (typically activate phase)
  | "demo_step"        // one step of a demonstration
  | "callout"          // points at a feature of an active visual
  | "challenge_setup"  // poses the question
  | "challenge_reveal" // reveals + explains the answer
  | "transition";      // bridge sentence between sub-ideas

export interface SegmentVisual {
  /**
   * Nano Banana Pro infographic prompt — narrowly scoped to THIS segment.
   * NOT a generic topic visual. Example for a Pythagoras lesson, segment
   * "the squares on each leg sum to the square on the hypotenuse":
   *   "Right triangle with legs 3 and 4, hypotenuse 5. Three squares
   *    drawn on each side, labeled 9, 16, 25. Equation 9 + 16 = 25
   *    written below in clean infographic typography."
   */
  prompt: string;

  /** What kind of image — affects style preset on the generation side. */
  style: "infographic" | "diagram" | "comparison" | "process_flow" | "annotated_photo";

  /** 1–3 short labels the avatar will reference in speech. */
  callouts?: string[];

  /**
   * Optional. If the LLM thinks this segment's visual should persist into the
   * next segment (e.g. the next segment elaborates on the same diagram),
   * set this true. Otherwise the visual fades when this segment ends.
   */
  persists_to_next?: boolean;
}

export interface NarrationSegment {
  id: string;             // "seg_001", "seg_002" — stable order
  phase: LessonPhase;
  role:  SegmentRole;
  text:  string;          // 1–3 sentences, what the avatar says
  visual?: SegmentVisual; // omit when no visual aid would help

  /**
   * Optional gesture hint. If omitted and visual is present, the playback
   * engine defaults to "pointing". If omitted and no visual, defaults to
   * "idle" (the avatar's talking animation pool plays automatically while
   * isSpeaking is true; gesture only overrides talking when explicitly set).
   */
  gesture?: "idle" | "pointing" | "thinking" | "explaining";

  /** Optional dwell time after narration ends, in seconds. Default 0. */
  pause_after?: number;
}

export interface LessonPayload {
  concept_id:   string;
  concept_name: string;

  /** ─── NEW: ordered segment list ─── */
  segments: NarrationSegment[];

  /**
   * 5-phase index — references segment IDs by phase.
   * UI uses this to render phase cards and the "next phase" button.
   * Each phase also keeps the small structured fields that aren't narration
   * (e.g. challenge.question is the prompt the student types into; it's not
   * narrated by the avatar — challenge_setup segments narrate it).
   */
  phases: {
    activate:    { segment_ids: string[]; prerequisites_referenced?: string[] };
    explain:     { segment_ids: string[]; key_insight?: string };
    demonstrate: { segment_ids: string[]; code?: string };
    challenge:   { segment_ids: string[]; question: string; hint: string; answer: string };
    connect:     { segment_ids: string[]; next_concept?: string };
  };

  metadata: {
    estimated_read_time_minutes: number;
    bloom_level_taught:          string;
    depth_level:                 string;

    /** Topic-level 3D model — kept, separate from segment 2D images.
     *  Renamed from `should_generate_model` to disambiguate. */
    should_generate_3d_model: boolean;
    model_3d_prompt?:         string;
    model_annotations?:       ModelAnnotation[];
  };
}
```

### 3.2 Example segment (heart anatomy lesson, explain phase)

```json
{
  "id": "seg_007",
  "phase": "explain",
  "role":  "narrate",
  "text":  "The mitral valve sits between the left atrium and left ventricle. Its job is one-way: blood flows down through it but never back up.",
  "visual": {
    "prompt":   "Cross-section of the human heart, zoomed into the left side, showing the mitral valve highlighted in red between the left atrium (top) and left ventricle (bottom). Arrow showing one-way blood flow downward. Clean medical illustration style, white background, labels in sans-serif.",
    "style":    "annotated_photo",
    "callouts": ["Left atrium", "Mitral valve", "Left ventricle"],
    "persists_to_next": true
  },
  "gesture":     "pointing",
  "pause_after": 0.5
}
```

The next segment might say *"When the ventricle squeezes, the valve snaps shut — that's half the heartbeat sound you hear"* and reuse the same image (`persists_to_next: true` on the prior segment), so we don't re-generate. The segment after that might pivot to a waveform diagram — new image, new prompt.

### 3.3 Example segment WITHOUT a visual

```json
{
  "id": "seg_008",
  "phase": "explain",
  "role":  "transition",
  "text":  "So that's the wiring. Now let's see what happens when something goes wrong with it.",
  "gesture": "idle"
}
```

The LLM decides this is verbal-only — no `visual` field. Avatar keeps talking, no image change.

## 4. Lesson agent changes — [src/lib/agents/teaching.ts](src/lib/agents/teaching.ts)

### 4.1 Tool schema update

The `tool_use` input schema for the `submit_lesson` tool changes from the current phase-blocks shape to the new `segments + phases.segment_ids` shape above. Anthropic's tool-use validates against the schema, so the LLM **cannot return malformed segments**.

### 4.2 System prompt additions

Add a "Visual Aid Rules" section to the system prompt — these rules are what stop the LLM from over-visualizing or under-visualizing:

```
VISUAL AID RULES — when to set segment.visual

DO set visual when the segment is about:
  • a physical structure or its parts (anatomy, cell, machine)
  • a geometric / spatial relationship (angles, areas, vectors)
  • a process with stages worth showing in parallel (mitosis, water cycle)
  • a comparison between 2-3 things best understood side-by-side
  • a labeled diagram clarifies a term that is otherwise abstract

DO NOT set visual when the segment is:
  • a transition or rhetorical question
  • a definition that is fully captured by the words themselves
  • a piece of code (the lesson UI already renders code blocks)
  • a recap or "so far we've seen…" sentence
  • the answer reveal of a challenge (use challenge_reveal role; the
    student's mental work matters more than another picture)

VISUAL PROMPT QUALITY
  • The prompt must be specific to THIS segment's content, not the lesson topic.
    Bad:  "anatomical diagram of the heart"  (every segment in the lesson)
    Good: "cross-section zoomed on the mitral valve, blood flow arrows
           pointing down through the open valve"  (this segment only)
  • Reference whatever the student should see in the picture. The avatar
    will literally point at these elements while narrating segment.text.
  • Keep prompts under 40 words. Concrete nouns + style hint.

PERSISTENCE
  • If the next 1–3 segments elaborate on the same visual, set
    persists_to_next: true on each one but the last in that run.
  • Don't generate a new image for every sentence — if the same diagram
    works for "the mitral valve sits here" + "and it opens like this"
    + "and snaps shut here", that's one image across three segments.

SEGMENT COUNT GUIDANCE
  • Typical lesson: 8–18 segments total
  • Of those: 3–6 should have visuals (33%-ish)
  • Don't pad. Better fewer, denser segments than many fragments.
```

### 4.3 Few-shot example

Add one full example lesson (Pythagoras, ~12 segments, 4 with visuals) to the system prompt. Few-shot is the single most reliable lever for getting the LLM to call `visual` correctly.

## 5. Image generation pipeline

### 5.1 New endpoint — [src/app/api/learn/segment-visuals/route.ts](src/app/api/learn/segment-visuals/route.ts)

```ts
POST /api/learn/segment-visuals
Body:    { segments: Array<{ id, prompt, style }> }
Returns: { results: Array<{ id, imageUrl?: string, error?: string }> }
```

Implementation:

1. Auth-gate (Supabase user) — same pattern as `/api/learn/lesson`.
2. Validate ≤ 8 segments per request (cost cap).
3. `Promise.all` — fire one Nano Banana Pro call per segment using the same fal.ai client already wired in [src/app/api/generate-model/route.ts](src/app/api/generate-model/route.ts). Style hint maps to a small preset prompt prefix:
   - `infographic` → `"educational infographic, clean typography, labeled, white background"`
   - `diagram`     → `"technical diagram, line art with subtle color, labeled axes"`
   - `comparison`  → `"side-by-side comparison, two panels, identical scale, labels"`
   - `process_flow` → `"horizontal flow chart, arrows between stages, numbered steps"`
   - `annotated_photo` → `"realistic illustration, callouts with thin lines to features"`
4. Per-segment failures don't fail the batch — return `error` in the result row and the playback engine falls back to "no visual for this segment" gracefully.
5. `maxDuration = 60`. Nano Banana Pro typically returns in 3–6s; 6 parallel requests should complete in 6–10s wall clock.

### 5.2 Caching

- Hash `(prompt + style)` → use as fal.ai idempotency key OR cache in Supabase Storage keyed by hash.
- A second student getting the same lesson re-uses cached images — meaningful savings since lesson content is deterministic-ish per concept.

### 5.3 Refactor [src/app/api/generate-model/route.ts](src/app/api/generate-model/route.ts)

Extract the Nano Banana Pro call into a shared helper at `src/lib/imagegen/banana.ts`:

```ts
export async function generateInfographic(opts: {
  prompt: string;
  style?: SegmentVisual["style"];
}): Promise<{ imageUrl: string }>;
```

Both `/api/generate-model` (topic-level 3D source image) and `/api/learn/segment-visuals` (per-segment educational images) consume it.

## 6. Playback engine — [src/hooks/useLessonPlayback.ts](src/hooks/useLessonPlayback.ts)

New hook. Single source of truth for "what segment is currently playing." Consumed by the new `LessonPlayer` component.

```ts
export interface LessonPlaybackState {
  segmentIdx:    number;          // current segment index
  isPaused:      boolean;
  isLoading:     boolean;         // true while segment visuals are being generated
  visualsByID:   Record<string, { imageUrl?: string; error?: string }>;
}

export interface LessonPlaybackControls {
  start:   () => void;
  pause:   () => void;
  resume:  () => void;
  next:    () => void;            // skip to next segment
  prev:    () => void;
  jumpToPhase: (phase: LessonPhase) => void;  // for the "next phase" button
}

export function useLessonPlayback(
  lesson: LessonPayload | null
): LessonPlaybackState & LessonPlaybackControls;
```

### 6.1 Playback algorithm

```
on lesson load:
  POST /api/learn/segment-visuals with all visual-bearing segments
  store results in visualsByID
  isLoading = false
  start at segment 0

per segment:
  1. resolve activeVisual:
       if segment.visual && visualsByID[segment.id]?.imageUrl
         → setActivePreviewImageUrl(imageUrl)
       elif previous segment had persists_to_next=true
         → keep previous image
       else
         → setActivePreviewImageUrl(null)

  2. resolve gesture:
       segment.gesture ?? (segment.visual ? "pointing" : "idle")
       → setGesture(...)

  3. setIsSpeaking(true)
     ttsController = useTTS().speak(segment.text, {
       onEnd: () => {
         setIsSpeaking(false)
         if segment.gesture === "pointing" → setGesture("idle")
         setTimeout(advance, (segment.pause_after ?? 0) * 1000)
       }
     })

  4. on advance:
       segmentIdx++
       if segmentIdx >= lesson.segments.length → mark lesson complete

on phase boundary (e.g. user clicks "Next phase"):
  ttsController.stop()
  jump segmentIdx to phases[nextPhase].segment_ids[0]
```

### 6.2 TTS prefetch (optional, ship in second iteration)

To eliminate the small gap between segments, extend `useTTS` to prefetch the next segment's MP3 while the current one is playing. The ElevenLabs `eleven_turbo_v2_5` endpoint returns `audio/mpeg` in ~0.5–1.5s for typical segment lengths; a single-slot prefetch hides this entirely.

### 6.3 Pause / resume behaviour

- Pause: `audio.pause()` + `setGesture("idle")`. State preserved.
- Resume: `audio.play()` + restore gesture.
- Skip: stop current TTS, advance to next segment immediately.

## 7. UI integration

### 7.1 New component — [src/components/learn/LessonPlayer.tsx](src/components/learn/LessonPlayer.tsx)

Replaces the per-phase TTS effects scattered through `LessonView.tsx`. - Highlights the current segment in the active phase card with a subtle left border / background tint so the student can follow which sentence is being narrated

## 8. Avatar gesture sync — already wired, small additions

The 2026-05-06 overhaul put the `gesture` state machine in place. Per-segment integration:

| Segment role | Default gesture (if not overridden) |
|--------------|-------------------------------------|
| `narrate`    | `pointing` if `visual` present, else `idle` |
| `hook`       | `idle` (idle pool's varied animations carry the energy) |
| `demo_step`  | `pointing` if visual, else `idle` |
| `callout`    | `pointing` always |
| `challenge_setup` | `explaining` (new — maps to talking pool with slight torso lean) |
| `challenge_reveal` | `nodding` if student got it right, `explaining` if not |
| `transition` | `idle` |

`explaining` is a new gesture value — add to the gesture union in the store and to `Teacher.tsx`'s pool resolution. For the Avaturn rig, fall back to the talking pool; on the rebaked Y_Bot animations, we can include a "Lecturing"-derived clip and pick that one when gesture is `explaining`.

## 9. Backwards compatibility & rollout

### 9.1 Feature flag

`NEXT_PUBLIC_ADAPTIVE_VISUALS` env var:
- `true` → new pipeline. Lesson agent emits segments. LessonPlayer mounts.
- unset / `false` → old pipeline. Lesson agent emits old phase blocks. Existing LessonView TTS effects run.

### 9.2 Dual-emit window

For the first 1–2 weeks, the lesson agent's tool schema includes BOTH the new `segments + phases.segment_ids` AND the old `phases.{activate,explain,…}.{content,formal_explanation,…}` fields. The LLM populates both. This lets us flip the flag back instantly if segment quality is bad.

### 9.3 Migration of in-flight users

`useLessonPlayback` checks `lesson.segments` — if absent, mounts a thin compatibility shim that synthesizes segments from the old phase blocks (one segment per phase, no visuals, gestures default to `idle`). This keeps anyone with a cached old lesson from breaking.

## 10. Cost & latency analysis

### 10.1 Cost per lesson

| Item | Today | After |
|------|-------|-------|
| Lesson generation (Sonnet 4.6) | ~$0.04 | ~$0.05 (slightly larger output for segments) |
| Topic image (Nano Banana Pro) | $0.04 (when triggered) | $0 (replaced by segment images) |
| Topic 3D (FLUX + Tripo3D) | $0.075 (when triggered) | $0.075 (kept, optional) |
| Segment images | $0 | 3–6 × $0.04 = $0.12–$0.24 |
| TTS (ElevenLabs turbo_v2_5) | ~free (≤10K chars/month free tier) | ~free (same) |
| **Total per lesson** | **~$0.13** | **~$0.27 (avg), $0.34 (with 3D)** |

~2× cost. Mitigated significantly by the cache (§5.2) once a concept's lessons stabilize — second + students hitting the same concept pay only TTS + lesson-gen.

### 10.2 Latency

- Lesson agent: 4–8s (unchanged)
- Segment visuals (parallel Nano Banana Pro): 6–10s for 6 images (new wait, currently 0)
- TTS streaming: starts in <1s per segment, prefetches mask gaps

Total wait from "student clicks lesson" to "avatar starts narrating": **~12–18s** (vs ~5–10s today). Acceptable with a clean loading state ("Preparing your visuals…" + an animated pencil-drawing line). For lessons without any visual segments (rare but possible — pure-abstract concepts), no visual wait at all.

## 13. Risks & mitigations

| Risk | Likelihood | Mitigation |
|------|------------|------------|
| LLM over-visualizes (every segment gets a picture) | Medium | Strict prompt rules + few-shot demonstrating restraint. Hard cap of 8 visuals/lesson at the API layer. |
| LLM under-visualizes (e.g. defaults to old behaviour, 0–1 visuals) | Medium | Few-shot with 4 visuals/12 segments shown explicitly. Telemetry — flag any lesson with 0 visuals on a clearly-physical concept. |
| Image generation failures cause lesson stall | Low | Per-segment errors are graceful — playback engine treats failed visuals as "no visual for this segment" and proceeds. |
| Segment images take too long → student stares at loading | Medium | Stream: start narrating segment 1 as soon as its image is ready, generate later segments' images in the background. (Phase F enhancement.) |
| Cost doubles | Confirmed | Cache aggressively. Most lessons in a school context get re-played by many students. |
| Avatar pointing fires for a segment whose visual failed | Low | Gesture resolution: `segment.visual && visualsByID[segment.id]?.imageUrl` → only then pointing. Otherwise default to talking. |
| Existing lessons in the wild break | Low | Compatibility shim in `useLessonPlayback` synthesizes segments from old phase blocks. |
| Schema change breaks the lesson API contract | Low | Dual-emit window. Old fields stay for 2 weeks before removal. |

## 14. Verification

### 14.1 Manual smoke tests (one per domain)

1. **Anatomy — "Heart valves"** (clearly physical)
   - Expect: 4–6 visual segments, images zoom in on different valves and flow paths, avatar points during each, talks transitionally between
2. **Geometry — "Pythagoras' theorem"** (spatial / mathematical)
   - Expect: 3–5 visual segments showing the right triangle, the squares on each side, the algebraic equation; visuals persist across "the same diagram" runs
3. **Abstract — "What is recursion?"** (mostly verbal)
   - Expect: 1–2 visual segments at most (call-stack diagram, or russian-doll metaphor); rest is verbal, gesture stays in talking pool

### 14.2 Automated checks

- Lint rule (custom): every `NarrationSegment` with `role === "callout"` must have `visual` set (callouts only make sense pointing at something)
- Lesson-quality CI: a GitHub action that calls `generateLesson()` against 10 fixed concepts and asserts segment count is 8–18 and visual count is 2–7

### 14.3 Rollback drill

Flip `NEXT_PUBLIC_ADAPTIVE_VISUALS=false`, redeploy, verify a known-good cached old-pipeline lesson still plays cleanly. Run before any production rollout.

## 15. Out of scope for this plan

- Video / animation per segment (vs static infographic) — interesting but expensive and slower. Revisit after the static-image version is stable.
- Streaming the lesson agent response so segments can render before generation finishes — major architectural change, deferred.
- Student-driven re-asking ("show me the valve again") — would re-trigger the relevant segment. Easy to add post-launch once the segment infrastructure is stable.
- Multi-language visual-aid prompts. Lesson agent currently outputs English; segment.visual.prompt is also English. Language sync deferred until the existing multilingual support is firm.
